# SwiftParcel ETA service: REST, MLflow, Ray Serve, smoke test

AIOps Module 4 - Assignment 5. A delivery-time (ETA) regression model (v1 = Ridge, v2 = gradient boosting) served four ways:

| Part | What it is | Main files |
|---|---|---|
| A | FastAPI REST service with validation, request IDs, Prometheus metrics, tests and a load-test analysis | `partA/eta_app.py`, `partA/test_eta_app.py` |
| B | MLflow model registry (aliases), multi-criteria promotion gate, shadow comparison | `partB/eta_mlflow.py`, `partB/test_gate.py`, `partB/shadow.py` |
| C | Ray Serve app with a sticky (per-customer) canary and autoscaling | `partC/eta_ray.py`, `partC/verify_ray.py` |
| D | Release-gate smoke test | `partD/smoke_eta.py` |

All results, tables and written answers are in **[REPORT.md](REPORT.md)**.


## Environment

Developed and run on: Ubuntu 26.04.1 LTS in a VirtualBox VM (8 vCPUs, about 9.6 GiB RAM), Python 3.14.4, CPU only. Package versions are listed in `REPORT.md`. Other operating systems and Python versions were not tested (the assignment states Python 3.10+).

## 1. One-time setup (from a clean checkout)

```bash
sudo apt update && sudo apt install -y python3 python3-venv python3-pip git
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python eta_data.py        # writes data/eta_train.csv, data/eta_fresh.csv, data/eta_v1.joblib, data/eta_v2.joblib
python -c "import pandas as pd, eta_data; pd.read_csv('data/eta_fresh.csv')[eta_data.FEATURES].head(200).to_csv('data/eta_sample.csv', index=False)"
```

`python eta_data.py` prints the fresh-data MAE of both models (about 11.95 min for v1 and 6.10 min for v2).

**In every new terminal, from the repository root, run:**

```bash
source env.sh
```

It activates the virtual environment, sets `PYTHONPATH` so the scripts in `partA`..`partD` can be imported, sets `MLFLOW_TRACKING_URI` to a SQLite file in the repository, and sets `OMP_NUM_THREADS=1` (and similar) so numerical libraries do not use extra threads, which matters for the load-test measurements. If you see `ModuleNotFoundError`, you probably forgot this step.

## 2. Part A - REST service

```bash
# tests (no server needed)
python -m pytest partA -v

# terminal 1: start the service (serves v1; use ETA_MODEL=data/eta_v2.joblib for v2)
source env.sh
uvicorn eta_app:app --port 8000 --log-level warning

# terminal 2: quick checks
source env.sh
curl -s localhost:8000/healthz
curl -s localhost:8000/metrics

# load test (4 s per level)
python load_test.py --url http://localhost:8000/v1/models/eta:predict --data data/eta_sample.csv \
       --concurrency 1 2 4 8 16 --duration 4 --out partA/loadtest_results.json
```

Endpoint: `POST /v1/models/eta:predict` with body `{"instances": [{distance_km, n_stops, hour, weekday, traffic_index, rain, weight_kg}, ...]}`. Invalid input returns 422 (`{"error": "validation_failed", "details": [...], "request_id": ...}`); a delivery with `distance_km > 150` and `n_stops > 20` is rejected as infeasible. Every response carries an `X-Request-ID` header.

For the two-worker experiment, stop the server and start it with `uvicorn eta_app:app --port 8000 --log-level warning --workers 2`, then repeat the load test and write to `partA/loadtest_results_workers2.json`. With several workers each process keeps its own metric counters.

## 3. Part B - MLflow

```bash
source env.sh
rm -rf mlflow.db mlruns                           # start from a clean registry
python partB/eta_mlflow.py register               # logs v1 and v2; aliases prod -> v1, candidate -> v2
python -m pytest partB -v                         # tests of decide()
python partB/eta_mlflow.py gate | tee partB/gate_output.txt
python partB/eta_mlflow.py gate --min-rel-gain 0.60 | tee -a partB/gate_output.txt
```

Shadow comparison needs **three terminals** (run `source env.sh` in each):

```bash
# terminal 1 (prod)
mlflow models serve -m "models:/eta-model@prod"      -p 5101 --env-manager local
# terminal 2 (candidate)
mlflow models serve -m "models:/eta-model@candidate" -p 5102 --env-manager local
# terminal 3 (wait until both servers are listening)
python partB/shadow.py | tee partB/shadow_output.txt
```

Stop both MLflow servers with Ctrl+C afterwards.

## 4. Part C - Ray Serve sticky canary

Stop anything using port 8000 first (for example the Part A server), then:

```bash
source env.sh
python partC/verify_ray.py | tee partC/verify_output.txt
```

The script starts its own Ray limited to 2 CPUs, deploys the app and runs five checks with assertions (candidate share at weight 0.2, stickiness, stickiness after redeploy, weight 0.2 to 0.5 never moves a candidate customer back, `X-Beta: 1` override). It prints `ALL CHECKS PASSED` on success and takes a few minutes. If a previous run left processes behind, run `ray stop --force` first.

## 5. Part D - smoke test

Start the Part A server (see section 2), then in another terminal:

```bash
source env.sh
python partD/smoke_eta.py --url http://localhost:8000/v1/models/eta:predict --expect-version v1 --max-p95-ms 80
echo "exit code: $?"          # 0 = all checks passed

# negative control: wrong expected version must fail with exit code 1
python partD/smoke_eta.py --url http://localhost:8000/v1/models/eta:predict --expect-version v2
echo "exit code: $?"
```

The abort criteria for a 10% canary are in `REPORT.md` (Part D).

## Common problems

| Symptom | Fix |
|---|---|
| `ModuleNotFoundError` for `eta_app`, `eta_data`, `eta_mlflow`, `eta_ray` | Run `source env.sh` from the repository root in this terminal. |
| `FileNotFoundError: data/eta_v1.joblib` | Run `python eta_data.py` from the repository root. |
| `Address already in use` | Find the process with `ss -ltnp \| grep 8000` and stop it (Ctrl+C or `pkill -f uvicorn`). Part C needs port 8000 free. |
| MLflow alias not found | Run `register` first, and use `source env.sh` in every terminal so they share the same `mlflow.db`. |
| Load-test numbers look strange | Make sure `source env.sh` was run in the server terminal (`echo $OMP_NUM_THREADS` should print 1), close other applications, and repeat. |
